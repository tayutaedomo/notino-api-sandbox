# 検証DBの手動復旧

この文書は、作成済みDBのIDが実行状態に残り、管理ファイルへの登録だけが中断した場合の復旧手順です。既存DBを確認して `pool.json` を補い、元の実行IDで後片付けを再開します。人またはAIが実施し、自動復旧の拡張は行いません。

## 対象と対象外

### この手順を使う場合

- DB作成成功のIDが `<実行ID>.json` の `resources.databases` に残っている。
- `pool.json` に同じDBの登録がない。
- 別の実行で初期DB作成を続けた際の中断など、自動復旧できない場合。

### この手順だけでは解決しない場合

- タイムアウトや5xxで作成結果が不明で、`pending` が残っている場合。
- 結果を確認せず、要求の再送や `pending` の削除をしません。
- その他の失敗や上限は[実API検証の対応方針](integration.md#失敗時の対応)を参照します。

## 復旧手順

### 1. プロセスを停止してバックアップする

- 検証プロセスとCLI子プロセスが終了していることを確認します。
- `.notion-test-runs/` 全体を、権限を維持してローカルにバックアップします。
- 復旧中は新規検証を起動しません。

### 2. 記録を照合する

- 対象の `<実行ID>.json` と `.jsonl`、`pool.json` を照合します。
- 実行状態の `resources.databases` から未登録IDを確認します。
- 管理ファイルの `attempted` から未登録の役割を確認します（Retro／Body／Sleep／Diary）。
- `request_started`・`request_finished` で、成功した作成要求との対応を確認します。

### 3. 実際のDBを確認する

検証用キーで `GET /v1/databases/<DB ID>` を実行し、次を確認します。

| 項目 | 必要な状態 |
|---|---|
| 親ページ | 実行状態と管理ファイルの `parent` に一致 |
| 名前 | `Notion API Test <pool.jsonのownerRunId> <役割>` と完全一致 |
| ゴミ箱 | 入っていない |
| データソース | 1件だけ |

- `GET /v1/data_sources/<データソースID>` で役割に必要なプロパティ型を確認します。
- DiaryはStatusの選択肢が1件以上あることも確認します。
- 複数候補があり対応を確定できなければ、管理ファイルを変更せず停止します。
- 読み取りにも[監査と通信制御](#復旧時の通信と記録)を適用します。

### 4. 管理ファイルを補完する

確認できた組み合わせだけを、`pool.json` の `databases` 配列へ追記します。

```json
{ "role": "Body", "id": "<確認済みDB ID>", "dataSourceId": "<確認済みデータソースID>" }
```

- 既存IDとの重複がないことを確認します。
- `ownerRunId` は初期作成の実行IDのまま維持します。
- `version`・`parent`・`attempted` と既存の登録を維持します。
- ファイル権限は0600にします。

### 5. 復旧操作を記録する

- [integration_safety.ts](../scripts/lib/integration_safety.ts) の `record` を使います。
- イベント名は `manual_pool_recovered` とします。
- 対象のJSONLログに復旧日時・役割・DB ID・データソースID・確認した所属と名前を記録します。
- トークンやレスポンス本文は記録しません。
- 実行状態の件数・開始日時・状態・`pending` はこの補完操作では変更しません。

### 6. 後片付けを再開する

```sh
# 予定確認
yarn test:integration --cleanup <中断した実行ID>
# 元の実行IDで再開
yarn test:integration --cleanup <中断した実行ID> --execute
# 終了したプロセスのロックが残る場合だけ、実行に --recover-lock を追加
```

- 完了をログで確認します。
- 次の検証は、24時間・累計回数の制限に従って必要な場合だけ実行します。

## 復旧時の通信と記録

### 読み取りの監査

- 対象の実行状態を使う `IntegrationTransport` を後片付けモードで利用します。
- その `fetch` を `createNotionClient` に渡します。
- 読み取りも操作ログ・1秒間隔・後片付け用通信上限に含めます。
- 枠が足りなければ自動で追加せず、ログと必要な操作を確認して判断します。

### 維持する状態

- DBの追加作成・削除は行いません。
- 履歴の削除や上限のリセットは行いません。
- AIへ依頼する場合は、この文書と対象の実行IDを渡します。

## 管理ファイルが消失した場合

- まずバックアップを復元します。
- バックアップがなければ、全履歴とDBの所属・名前・スキーマを照合してから再構成します。
- 空の管理ファイルを作って検証を再実行する方法は使いません。
